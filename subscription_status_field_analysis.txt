VERDICT: BusinessProfile fields are DERIVED from MobileSubscription and should not be used as primary source.

================================================================================
FINAL ANALYSIS ANSWERS
================================================================================

1. WHY DOES isActive BECOME TRUE WHEN STATUS=PENDING?

ANSWER: Data inconsistency between MobileSubscription and BusinessProfile tables.
When BusinessProfile.subscriptionStatus = 'ACTIVE' and BusinessProfile.isSubscriptionActive = true,
but MobileSubscription.status = 'PENDING', the API can return conflicting data.

The business profile path uses:
```javascript
const isActive = (profile.subscriptionStatus === 'ACTIVE') && !!profile.isSubscriptionActive;
```

If the business profile fields are stale (not updated by cancellation webhook), isActive=true even though the actual subscription status is PENDING.

2. WHICH FIELD SHOULD REPLACE isActive?

ANSWER: MobileSubscription.status

REASONING:
- Primary source of truth directly updated by Razorpay webhooks
- Strictly typed ENUM preventing invalid values
- No dependency on derived fields that can become inconsistent
- Single source of truth for subscription state

3. WHAT SHOULD THE CORRECT API RESPONSE FORMAT BE?

ANSWER: Use MobileSubscription.status as the primary field and remove derived isActive field.

RECOMMENDED RESPONSE:
```javascript
{
  "subscriptionStatus": "PENDING",
  "planId": "rzp_test", 
  "planName": "RZP_Test",
  "expiryDate": "2026-04-28T10:35:50.674Z",
  "autoRenew": true
}
```

FRONTEND LOGIC SHOULD BE:
```javascript
const isActive = subscriptionStatus === 'ACTIVE';
```

CONCLUSION

MobileSubscription.status (primary source) and BusinessProfile fields (derived source).

The solution is to use MobileSubscription.status as the single source of truth and
remove the derived isActive field from API responses.

Frontend should compute active state: isActive = subscriptionStatus === 'ACTIVE'
