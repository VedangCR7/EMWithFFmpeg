DETAILED ANALYSIS
=================

1. CURRENT CLOUDINARY USAGE
---------------------------
- Images fetched from: calendarApi service → backend API → Cloudinary URLs
- URL transformation happens in multiple places:
  * getHighQualityThumbnailUrl() in HorizontalFestivalCalendar (lines 308-346)
  * applyCloudinaryTransform() in OptimizedImage (lines 94-141)
  * optimizedThumbnailUri in ThumbnailImage (lines 67-95)
  * optimizedFullImageUri in LazyFullImage (lines 58-105)

2. IDENTIFIED ISSUES
-------------------

A. PERFORMANCE ISSUES:
- getHighQualityThumbnailUrl recalculates on every render (line 555, 626, 744)
- Using w_1200 for small thumbnail cards (actual card width: 55-66px)
- Multiple transformation functions create redundant processing
- No memoization of transformed URLs

B. OPTIMIZATION OPPORTUNITIES:
- Thumbnail cards should use w_100-200 instead of w_1200
- Modal cards should use w_400-600 instead of w_1200
- Missing f_auto,q_auto,c_fill combination for better compression
- No device pixel ratio consideration for consistent quality

C. CACHING STRATEGY:
- ThumbnailImage uses 7-day cache (good for thumbnails)
- OptimizedImage has no persistent caching
- No cache invalidation strategy for updated images

3. SPECIFIC OPTIMIZATIONS NEEDED
---------------------------------

A. HORIZONTAL FESTIVAL CALENDAR:
- Replace getHighQualityThumbnailUrl with size-aware transformation
- Add useMemo for URL transformations
- Use appropriate sizes:
  * Calendar date cells: w_50-75 (not applicable - no images)
  * Thumbnail cards: w_150-200
  * Modal cards: w_400-500

B. UNIFIED TRANSFORMATION FUNCTION:
- Create single, memoized Cloudinary URL transformer
- Support responsive widths based on container size
- Consistent quality settings across components

C. CACHING IMPROVEMENTS:
- Implement cache versioning for invalidation
- Reduce ThumbnailImage cache to 3 days for fresher content
- Add cache size limits to prevent storage bloat
