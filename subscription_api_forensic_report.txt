API: GET /api/mobile/subscriptions/status
File: deployment_server.js
Line: 5817

BUGGY CODE:
```javascript

```

🔥 ROOT CAUSE:
The condition `(bridgedSubscription?.autopayEnabled && subscriptionStatus === 'PENDING')`
incorrectly sets isActive=true for PENDING subscriptions when autopayEnabled=true.

This means:
- When user cancels Razorpay payment → subscription.status = 'CANCELLED'
- BUT if autopayEnabled=true → isActive=true (INCORRECT!)
- Frontend receives: { status: "cancelled", isActive: true } ❌

CORRECT LOGIC SHOULD BE:
```javascript
isActive: subscriptionStatus === 'ACTIVE',
```

SECTION 8 — EXACT API RESPONSIBLE FOR THE BUG
================================================================================

🎯 BUG LOCATION IDENTIFIED:

API: GET /api/mobile/subscriptions/status
File: deployment_server.js
Line: 5817

EXACT BUGGY CODE:
```javascript
isActive: subscriptionStatus === 'ACTIVE' || (bridgedSubscription?.autopayEnabled && subscriptionStatus === 'PENDING'),
```

PROBLEM EXPLANATION:
1. User cancels Razorpay payment
2. Razorpay sends subscription.cancelled webhook
3. Webhook correctly updates subscription.status='CANCELLED'
4. BUT subscription.autopayEnabled=true remains true
5. API query includes: { status: 'PENDING', autopayEnabled: true }
6. API incorrectly finds cancelled subscription via OR condition
7. Sets subscriptionStatus='PENDING' (wrong) and isActive=true (wrong)

FLOW TRACING:
Database: subscription.status='CANCELLED', autopayEnabled=true
↓
API Query: OR [{ status: 'ACTIVE' }, { status: 'PENDING', autopayEnabled: true }]
↓
API finds CANCELLED subscription but treats it as PENDING due to autopayEnabled
↓
Response: { status: "pending", isActive: true } ❌

FINAL RESULT
================================================================================

ANSWER TO THE INVESTIGATION QUESTION:

Which API or backend function is incorrectly setting the subscription to ACTIVE when payment is cancelled?

🎯 **ANSWER: GET /api/mobile/subscriptions/status API in deployment_server.js**

The bug is in the subscription status API response builder at line 5817, where the condition:
`(bridgedSubscription?.autopayEnabled && subscriptionStatus === 'PENDING')`
incorrectly marks cancelled subscriptions as active when autopay is enabled.

This is compounded by incorrect query logic that includes PENDING subscriptions with autopayEnabled=true,
and status assignment logic that forces non-ACTIVE subscriptions to be reported as 'PENDING'.

The fix requires removing all autopayEnabled-based activation logic and only allowing
subscription.status === 'ACTIVE' to return isActive=true.
