### 10.2 New Middleware: Business Profile Download Limit
```typescript
export const checkBusinessProfileDownloadLimit = async (
  req: Request, 
  res: Response, 
  next: NextFunction
) => {
  const { mobileUserId, businessProfileId } = req.body;
  
  // 1. Validate business profile belongs to user
  const businessProfile = await prisma.businessProfile.findFirst({
    where: {
      id: businessProfileId,
      mobileUserId: mobileUserId,
      isActive: true
    }
  });
  
  if (!businessProfile) {
    return res.status(403).json({
      success: false,
      error: 'Invalid business profile'
    });
  }
  
  // 2. Get user timezone (fallback to UTC)
  const userTimezone = req.headers['x-user-timezone'] || 'UTC';
  
  // 3. Calculate start of day in user's timezone
  const startOfToday = getStartOfDayInTimezone(new Date(), userTimezone);
  
  // 4. Count downloads today for this business profile
  const downloadCount = await prisma.mobileDownload.count({
    where: {
      businessProfileId: businessProfileId,
      createdAt: { gte: startOfToday }
    }
  });
  
  // 5. Check against daily limit
  if (downloadCount >= 5) {
    return res.status(403).json({
      success: false,
      error: 'Daily download limit reached',
      message: 'You can download 5 posters per day per business profile',
      remainingDownloads: 0,
      resetTime: getNextDayResetTime(userTimezone)
    });
  }
  
  // 6. Add remaining downloads to request for response
  req.remainingDownloads = 5 - downloadCount;
  next();
};
```

### 10.3 Timezone Handling Utility
```typescript
function getStartOfDayInTimezone(date: Date, timezone: string): Date {
  const utcDate = new Date(date.toLocaleString("en-US", {timeZone: timezone}));
  utcDate.setHours(0, 0, 0, 0);
  return utcDate;
}

function getNextDayResetTime(timezone: string): string {
  const tomorrow = new Date();
  tomorrow.setDate(tomorrow.getDate() + 1);
  tomorrow.setHours(0, 0, 0, 0);
  return tomorrow.toLocaleString("en-US", {timeZone: timezone});
}
```

## 11. EDGE CASES TO HANDLE

### 11.1 Multiple Devices
**Scenario**: User downloads from multiple devices for same business profile
**Solution**: Count downloads per business profile across all devices (current system handles this)

### 11.2 Failed Downloads
**Scenario**: Download tracking succeeds but file save fails
**Solution**: Only track successful downloads (current system does this correctly)

### 11.3 Business Profile Switching
**Scenario**: User switches business profiles during download session
**Solution**: Each profile has independent download limits

### 11.4 Timezone Changes
**Scenario**: User travels across timezones
**Solution**: Use consistent timezone based on user's profile setting or last known timezone

### 11.5 Retry Logic
**Scenario**: User retries failed download
**Solution**: Current duplicate prevention handles this, but limit should only count successful downloads

### 11.6 Offline Downloads
**Scenario**: App works offline and syncs later
**Solution**: Track downloads when online, validate limits at sync time

### 11.7 Calendar Posters vs Templates
**Scenario**: Different resource types with different limits
**Solution**: Apply same 5-download limit across all resource types per business profile
