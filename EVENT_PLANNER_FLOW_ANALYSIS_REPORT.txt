PART 4: FILTERING LOGIC (CORE)
================================================================================

1. SINGLE SOURCE OF TRUTH:
   - Source: serviceFilterTemplates['eventplanner'] (cached templates)
   - No dependency on allTemplates for filtering
   - Templates fetched once and cached

2. FILTERING TRIGGER:
   - Condition: isEventPlannerCategory && selectedServiceFilter && serviceFilterTemplates['eventplanner']
   - useEffect dependencies: [isEventPlannerCategory, selectedServiceFilter, serviceFilterTemplates]

3. FILTERING PIPELINE:
   Step 1: Get cached EventPlanner templates
   Step 2: Map templates with mergeTemplateLanguages()
   Step 3: Filter by service keywords using tagsMatchCategory()
   Step 4: Apply language filter if not 'all'
   Step 5: Limit to 6 templates

4. MATCHING SYSTEM:
   - Function: tagsMatchCategory(templateTags, keywords)
   - Exact tag matching (case-insensitive)
   - Template must include at least one keyword
   - No fuzzy matching or loose criteria

5. NO FALLBACK LOGIC:
   - Empty results returned as-is
   - No mixing with other template sources
   - No fallback to allTemplates

================================================================================
PART 5: AUTO-SELECTION BEHAVIOR
================================================================================

1. NO AUTO-SELECTION LOGIC:
   - Event Planner flow has NO dedicated auto-selection
   - Relies on initialPoster from navigation params
   - No useEffect for automatic poster selection

2. SELECTION PRESERVATION:
   - currentPosterIndex finds poster in filteredPosters
   - ID-based matching first, thumbnail fallback
   - Preserves user selection across filter changes

3. LANGUAGE CHANGE HANDLING:
   - Separate useEffect for language filtering
   - Attempts to preserve current poster if language matches
   - Falls back to first matching template

PART 6: LOADING & TIMING CONTROL
================================================================================

1. LOADING STATE:
   - State: isLoadingServiceFilter.eventplanner
   - Set to true before API call
   - Set to false in finally block

2. TIMING GUARDS:
   - Templates fetched only when activeRenderSource === 'profile'
   - Cache check prevents duplicate API calls
   - 5-minute cache duration

3. RACE CONDITION PREVENTION:
   - Single source control prevents conflicting filters
   - Service filter reset when not Event Planner category
   - No filtering during loading state

================================================================================
PART 7: RENDERING PIPELINE
================================================================================

1. RENDERING PRIORITY:
   - First: currentPoster (if exists in filteredPosters)
   - Second: filteredPosters[0] (first filtered template)
   - Fallback: filteredPosters array

2. INDEX CALCULATION:

   - ID-based matching with thumbnail fallback
   - Returns -1 if not found

3. NO FLICKER BEHAVIOR:
   - Templates cached before filtering
   - Instant filtering from cached data
   - No loading states during filter changes
