# PosterPlayerScreen Deep Analysis Report

## 1. PosterPlayerScreen Overview

PosterPlayerScreen is a complex, multi-purpose screen that displays posters in a preview format with a grid below for browsing. It handles multiple data sources:
- Business category posters (from business profiles)
- Greeting category posters (from greeting templates)
- Calendar posters (from calendar dates)
- General poster browsing (from related posters)

The screen features:
- Large poster preview with swipe navigation
- Language filtering (All, English, Hindi)
- Service filtering for Event Planner category
- Responsive grid layout for related posters
- Navigation to PosterEditor
- Complex state management for poster selection and filtering

## 6. Poster Loading System

### Business Category Loading
**API Endpoint:** `/api/mobile/posters/category/${categoryName}?limit=${limit}`
**Service:** `businessCategoryPostersApi.getPostersByCategory()`
**Cache:** Clears category cache before fetch
**Limit:** 1000 for "My Business", 5 for other cases

### Greeting Category Loading  
**Multiple API Calls:**
1. `greetingTemplatesService.getTemplates({ category, limit: 50 })`
2. `greetingTemplatesService.searchTemplates(category, undefined, 50)`
3. `greetingTemplatesService.searchTemplates(normalizedCategory, undefined, 50)`
4. Variations with individual words (up to 3 variations)

**Progressive Loading:**
- Initial 50 items for fast render
- Background load of 200 items after render
- Strict category filtering to prevent cross-contamination

### Calendar Loading
**API Endpoint:** `calendarApi.getPostersByDate(date)`
**Template Conversion:** Maps CalendarPoster to Template format

## 13. Risk Analysis

### Shared States
**Risk:** BusinessProfile context changes could affect both screens
**Mitigation:** Use separate navigation param for business category

**API Cache Conflicts:**
**Risk:** businessCategoryPostersApi cache could serve stale data
**Mitigation:** Clear cache specifically for user's category before fetching

**Memory Leaks:**
**Risk:** Complex useEffect dependencies could cause infinite re-renders
**Mitigation:** Careful dependency arrays and ref usage for tracking

**Race Conditions:**
**Risk:** Multiple category useEffects could overwrite each other
**Mitigation:** Use activeCategoryRef pattern for protection

**Navigation State:**
**Risk:** Global language state could conflict between screens
**Mitigation:** Maintain separate language state or reset on mount

useEffect(() => {
  const fetchBusinessPosters = async () => {
    setLoading(true);
    try {
      // Clear cache for fresh data
      businessCategoryPostersApi.clearCategoryCache(businessCategory);
      
      const response = await businessCategoryPostersApi.getPostersByCategory(
        businessCategory, 
        posterLimit || 200
      );
      
      if (response.success && response.data.posters) {
        const templates = response.data.posters.map(convertToTemplate);
        setBusinessPosters(templates);
        
        // Set first poster as current if none selected
        if (!currentPoster && templates.length > 0) {
          setCurrentPoster(templates[0]);
        }
      }
    } catch (error) {
      console.error('Error fetching business posters:', error);
    } finally {
      setLoading(false);
    }
  };
  
  fetchBusinessPosters();
}, [businessCategory, posterLimit]);
