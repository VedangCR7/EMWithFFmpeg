2. FORGOT PASSWORD FLOW SUMMARY
======================================

COMPLETE FLOW TRACING:
---------------------

Step 1: User clicks "Forgot Password" on LoginScreen
Step 2: Navigate to ForgotPasswordScreen
Step 3: User enters email address
Step 4: Call API to request password reset
Step 5: Backend sends 6-digit OTP to email
Step 6: Show success alert and navigate to VerifyResetCodeScreen
Step 7: User enters 6-digit code
Step 8: Verify code via API
Step 9: Navigate to ResetPasswordScreen
Step 10: User enters new password and confirm
Step 11: Submit password reset via API
Step 12: Show success and navigate back to LoginScreen

API ENDPOINTS USED:
------------------
1. POST /api/mobile/auth/forgot-password - Request reset code
2. POST /api/mobile/auth/verify-reset-code - Verify OTP code
3. POST /api/mobile/auth/reset-password - Reset password with code

REQUEST/RESPONSE FLOW:
---------------------

FORGOT PASSWORD REQUEST:
- API: loginAPIs.requestPasswordReset({ email })
- Endpoint: POST /api/mobile/auth/forgot-password
- Request Body: { email: "user@example.com" }
- Response: { success: true, message: "Code sent" }

NAVIGATION TRIGGER:
- Alert dialog with "OK" button
- On OK press: navigation.navigate('VerifyResetCode', { email })
- Route params: { email: string }

SUBMIT HANDLER CODE SNIPPET:
----------------------------
const handleVerify = useCallback(async () => {
  if (!isCodeValid) {
    Alert.alert('Invalid Code', 'Please enter the 6-digit code sent to your email.');
    return;
  }

  setIsSubmitting(true);
  try {
    await loginAPIs.verifyResetCode({ email, code });
    navigation.navigate('ResetPassword', { email, code });
  } catch (error: any) {
    const message = error?.response?.data?.message || error.message || 'Verification failed. Please try again.';
    Alert.alert('Verification Failed', message);
  } finally {
    setIsSubmitting(false);
  }
}, [code, email, isCodeValid, navigation]);

API CALL DETAILS:
-----------------
- Function: loginAPIs.verifyResetCode({ email, code })
- Endpoint: POST /api/mobile/auth/verify-reset-code
- Request Body: { email: "user@example.com", code: "123456" }
- Success Response: { success: true, message: "Code verified" }

SUCCESS NAVIGATION:
------------------

- Pass params: { email, code }
- Both email and verified code forwarded to next screen

FAILURE HANDLING:
----------------

4. RESEND LOGIC SUMMARY
======================================

RESEND BUTTON EXISTS:
-------------------
Yes - Resend functionality implemented in VerifyResetCodeScreen

RESEND HANDLER CODE SNIPPET:
----------------------------
const handleResend = useCallback(async () => {
  setIsSubmitting(true);
  try {
    await loginAPIs.requestPasswordReset({ email });
    Alert.alert('Code Resent', 'A new verification code has been sent to your email.');
    setResendTimer(30);
  } catch (error: any) {
    const message = error?.response?.data?.message || error.message || 'Unable to resend code right now.';
    Alert.alert('Resend Failed', message);
  } finally {
    setIsSubmitting(false);
  }
}, [email]);

TIMER LOGIC:
-----------
- Initial timer: 30 seconds after successful resend
- Countdown: Decrements every second using setInterval
- Button disabled when timer > 0
- Timer resets to 30 on each successful resend

RATE LIMITING:
-------------
- Client-side: 30-second cooldown between resends
- Server-side: Backend may have additional rate limiting
- Visual feedback: Timer shown on resend button

API CALL FOR RESEND:
-------------------
- Function: loginAPIs.requestPasswordReset({ email })
- Same endpoint as initial request
- Backend generates new OTP code
- Previous code becomes invalid

ERROR HANDLING:
-------------
- Network errors: Alert with "Unable to resend code right now"
- Server errors: Display server error message
- User can retry after timer expires
