# DUPLICATE POSTERS IN MYPOSTERSCREEN - DEEP ANALYSIS REPORT

## SYSTEM ARCHITECTURE OVERVIEW

The application follows a hybrid architecture with both frontend (React Native) and backend API components in the same repository:

### Frontend Components:
- **React Native Mobile App**: Located in `src/` directory
- **Download Tracking**: Multiple services handle download operations
- **State Management**: Local AsyncStorage + Backend API synchronization

### Backend Components:
- **API Endpoints**: RESTful API at `/api/mobile/downloads/*`
- **Download Tracking**: Server-side tracking via `downloadTrackingService`
- **Data Storage**: Backend database (not visible in repo) + Local AsyncStorage fallback

## BACKEND DOWNLOAD API ANALYSIS

### Key API Endpoints:
1. **Track Download**: `POST /api/mobile/downloads/track`
   - Called by: `downloadTrackingService.trackDownload()`
   - Purpose: Record download event in backend
   - Parameters: `mobileUserId`, `resourceType`, `resourceId`, `fileUrl`, `title`, `thumbnail`, `category`

2. **Get User Downloads**: `GET /api/mobile/users/{userId}/downloads`
   - Called by: `downloadTrackingService.getUserDownloads()`
   - Purpose: Retrieve all downloads for a user
   - Returns: Array of download objects with metadata

### Download Flow Analysis:
```
User clicks download → 
trackDownload() → 
API POST /api/mobile/downloads/track → 
Backend saves to database → 
Cache cleared → 
MyPostersScreen refreshes → 
API GET /api/mobile/users/{userId}/downloads → 
Display posters
```

## DATABASE SCHEMA ANALYSIS

### Database Tables (Inferred from API responses):
- **Downloads Table**: Stores download records
  - Fields: `id`, `mobileUserId`, `resourceType`, `resourceId`, `fileUrl`, `title`, `thumbnail`, `category`, `createdAt`
  - **CRITICAL MISSING**: No unique constraints on `(mobileUserId, resourceId, resourceType)` combination

### Key Finding:
- **No Composite Unique Key**: Backend allows duplicate entries for same user downloading same poster multiple times
- **Missing Deduplication Logic**: Backend doesn't check for existing downloads before inserting new records

async trackDownload(userId, resourceType, resourceId, fileUrl, additionalData) {
  const response = await api.post('/api/mobile/downloads/track', {
    mobileUserId: userId,
    resourceType: resourceType,
    resourceId: resourceId,
    fileUrl: fileUrl,
    ...additionalData

  };

### CRITICAL DUPLICATION SOURCES IDENTIFIED:

#### Source 1: Double API Calls
- **PosterPreviewScreen.tsx** (Line 382): Calls `downloadedPostersService.savePosterInfo()`
- **businessCategoryPostersApi.ts** (Line 324): Also calls download tracking API
- Both services can be triggered for same download action

#### Source 2: Local Storage Duplication
- **downloadedPosters.ts** (Line 53): Uses `Date.now().toString()` for ID
- **downloadedPosters.ts** (Line 53): Simple array append without deduplication check
- **Result**: Same poster can be saved multiple times with different IDs

#### Source 3: Cache Invalidation Issues
- **downloadTracking.ts** (Line 166): Clears cache after every download
- **MyPostersScreen.tsx** (Line 129): Also clears cache on focus
- **Result**: Race conditions can cause stale data display

## ROOT CAUSE OF DUPLICATE POSTERS

### PRIMARY ROOT CAUSE: BACKEND MISSING UNIQUE CONSTRAINTS

**Evidence:**
1. **No Database Constraints**: Backend allows multiple download records for same `(userId, resourceId, resourceType)`
2. **Duplicate API Responses**: `getUserDownloads()` returns multiple entries for same poster
3. **Frontend Compensation**: MyPostersScreen has deduplication logic to handle backend duplicates

### SECONDARY CONTRIBUTING FACTORS:

1. **Multiple Download Entry Points**:
   - `PosterPreviewScreen.tsx` (Line 382)
   - `businessCategoryPostersApi.ts` (Line 324)
   - Different components can trigger download for same poster

2. **Race Conditions**:
   - Cache clearing at multiple points
   - Async operations without proper sequencing
   - `useFocusEffect` triggers multiple times during navigation

3. **Local Storage Fallback**:
   - `downloadedPosters.ts` saves to AsyncStorage without duplicate checks
   - Uses `Date.now()` for IDs, allowing same poster multiple times

## CONCLUSION

**Root Cause**: Backend database lacks unique constraints on download records, allowing the same user to download the same poster multiple times.

**Primary Evidence**: 
- Multiple API endpoints can track downloads without coordination
- No server-side duplicate prevention
- Frontend has compensating deduplication logic
- Local storage allows duplicate entries

**Impact**: Users see duplicate posters in MyPostersScreen, creating confusing user experience and data integrity issues.

**Priority**: HIGH - Requires backend database constraint fixes and API deduplication logic.
