5. TRANSACTION DATA MAPPING DETAILS
=================================

UNIFIED API RESPONSE STRUCTURE:
{
  success: boolean,
  transactions: [
    {
      id: string,
      type: "subscription" | "business_profile",
      amount: number,
      currency: string,
      status: "success" | "failed" | "pending" | "cancelled",
      paymentMethod: string,
      orderId: string,
      paymentId: string,
      createdAt: string,
      metadata?: object
    }
  ]
}

FRONTEND TRANSACTION INTERFACE:
{
  id: string,
  paymentId: string,
  orderId: string,
  amount: number,
  currency: string,
  status: 'success' | 'failed' | 'pending' | 'cancelled',
  plan: 'quarterly' | 'yearly' | 'business_profile',
  planName: string,
  timestamp: number,
  description: string,
  method: 'razorpay',
  metadata?: object,
  type: 'subscription' | 'business_profile'
}

MAPPING LOGIC:
- type: Direct mapping from backend type field
- plan: Derived from type and plan content
- planName: Backend field or fallback based on type
- timestamp: Converted from createdAt string to number
- description: Backend field or generated fallback
- method: Backend paymentMethod or 'razorpay' fallback
- metadata: Parsed if string, passed through if object
