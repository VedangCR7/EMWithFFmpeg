1. OVERVIEW OF BusinessProfileForm COMPONENT
================================================

The BusinessProfileForm component is responsible for collecting business profile data
including the company logo. Key state variables:
- formData: Contains form fields including companyLogo (initialized as empty string)
- logoImage: Stores the local image URI for preview display
- uploadingImage: Loading state during image upload

The form uses a two-step approach:
1. Image selection stores the local URI in formData.companyLogo
2. Form submission handles logo differently for new vs existing profiles

5. EXACT REASON WHY LOGO IS EMPTY
================================================

ROOT CAUSE ANALYSIS:

The logo is empty because of a BROKEN TWO-STEP UPLOAD FLOW:

STEP 1 (Form Submission):
- BusinessProfileForm.handleSubmit() checks if logo is a local file path
- If YES, it REMOVES the logo from the payload (companyLogo: '', logo: '')
- It stores the logo URI in AsyncStorage as `pending_logo_${profileId}`
- It submits the form WITHOUT the logo to the backend

STEP 2 (Intended Post-Creation Upload):
- The code INTENDS to upload the logo after profile creation
- However, THERE IS NO CODE that retrieves the pending logo from AsyncStorage
- THERE IS NO CODE that uploads the logo after profile creation
- The pending logo remains in AsyncStorage forever

EVIDENCE:
- Line 504 in BusinessProfileForm: Strips logo from payload
- Line 566 in BusinessProfilesScreen: Stores pending logo in AsyncStorage
- NO CODE found that retrieves `pending_logo_${profileId}`
- NO CODE found that calls uploadImage() after profile creation

The comment in line 502-503 states:
"For new profiles, we need to create the profile first, then upload the image"
But the implementation is INCOMPLETE - the "then upload the image" part is missing.

7. RECOMMENDED FIX
================================================

The issue can be fixed using one of these approaches:

APPROACH A: Upload Logo BEFORE Profile Creation (RECOMMENDED)
-------------------------------------------------------------
This approach is simpler and more reliable:

1. Remove the two-step upload logic from BusinessProfileForm
2. Always submit the form with the logo included
3. Change the API to accept FormData instead of JSON
4. Include the logo file in the FormData along with other fields
5. Backend processes both profile creation and logo upload in one request

PROS:
- Single atomic operation - either both succeed or both fail
- Simpler code flow
- No pending state to manage
- No cleanup needed

CONS:
- Requires backend API change to accept multipart/form-data
- Slightly larger payload

APPROACH B: Implement Complete Two-Step Upload (CURRENT INTENT)
----------------------------------------------------------------
Complete the existing two-step upload flow:

1. Keep the current logic of stripping logo from initial request
2. After profile creation succeeds, retrieve pending logo from AsyncStorage
3. Upload the logo using businessProfileService.uploadImage()
4. Update the profile with the uploaded logo URL
5. Remove the pending logo from AsyncStorage

PROS:
- Keeps existing API contract (JSON for profile creation)
- Separates concerns (profile creation vs file upload)

CONS:
- More complex code flow
- Multiple API calls
- Need to handle partial failures
- Need cleanup logic for orphaned pending logos

APPROACH C: Send Local File Path to Backend (NOT RECOMMENDED)
-------------------------------------------------------------
Send the local file path to backend and let backend handle upload.

PROS:
- Minimal frontend changes

CONS:
- Backend cannot access device local file system
- Security risk
- Not feasible for mobile apps

async createBusinessProfile(data: CreateBusinessProfileData): Promise<BusinessProfile> {
  try {
    console.log('Creating business profile via API:', data.name);
    
    const currentUser = authService.getCurrentUser();
    const ownerNameFromUser = currentUser?.name || currentUser?.companyName || currentUser?.displayName || currentUser?.firstName;
    const ownerNameFallback = currentUser?.email
      ? currentUser.email.split('@')[0]
      : (data.name ? `${data.name} Owner` : 'Business Owner');
    const ownerName = (ownerNameFromUser && ownerNameFromUser.trim()) || ownerNameFallback;

    const businessName = (data.name || '').trim();

    const isLocalLogo = logoUrl && this.isLocalFilePath(logoUrl);

        uri: logoUrl,
        type: mimeType,

        headers: {
          'Content-Type': 'multipart/form-data',

9. FINAL CONCLUSION
================================================

ROOT CAUSE:
The logo field is empty because the BusinessProfileForm implements a two-step upload
flow that is INCOMPLETE. When creating a new profile with a local file path logo:

1. The form STRIPS the logo from the payload (companyLogo: '', logo: '')
2. It stores the logo URI in AsyncStorage as pending
3. The backend receives an empty logo field
4. The pending logo is NEVER retrieved or uploaded
5. The logo remains in AsyncStorage forever, unused

EVIDENCE:
- BusinessProfileForm.tsx line 504: Intentionally removes logo from payload
- BusinessProfilesScreen.tsx line 566: Stores pending logo but never retrieves it
- No code found to upload logo after profile creation
- Backend receives empty string for logo field

RECOMMENDATION:
Implement Approach A (FormData multipart upload) as it's simpler, more reliable,
and provides atomic operation. If backend changes are not possible, implement
Approach B (complete two-step upload) by adding the missing upload logic after
profile creation.

IMPACT:
- All new business profiles created with a logo will have an empty logo field
- Users must manually edit the profile to add the logo after creation
- Pending logos accumulate in AsyncStorage, causing storage bloat

PRIORITY: HIGH
This is a critical bug affecting user experience and data integrity.
