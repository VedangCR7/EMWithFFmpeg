5. Debug Findings

Based on the code analysis, here are the likely scenarios causing the bug:

Scenario A: Incorrect API Tags
- Posters from API may have incorrect or mixed tags
- Example: A poster meant for "Mobile App Development" might have tags: ['website', 'mobile']
- This would cause it to appear in both categories

Scenario B: Tag Assignment Issue
- Line 292: `languages: poster.tags || []` assigns the same tags to both languages and tags fields
- While this shouldn't affect category filtering (which uses tags), it indicates potential data structure confusion

Expected debug output for Mobile App Development selection:
```
🏷️ [CATEGORY FILTER] Filtering by category: Mobile App Development
🏷️ [CATEGORY FILTER] Category tags: [mobile]
🔍 [MATCH DEBUG] Tag "mobile" matched for poster "Poster Name":
   - Exact tag match: true
   - Poster tags: [mobile, website]  ← Problem: Multiple tags
```

6. Root Cause

The root cause is likely **incorrect tagging in the backend API data**:

**Primary Issue**: Posters intended for "Mobile App Development" category are being returned from the API with multiple tags including both 'mobile' and 'website'.

**Evidence**:
1. Category button configuration is correct with distinct tags
2. Filtering logic is correct and uses exact tag matching
3. Category selection flow is working properly
4. The only remaining variable is the actual poster.tags data from API

**Specific Problem**: 
- Backend API is returning posters with tags like: ['website', 'mobile'] or ['website', 'mobile', 'app']
- When user selects "Mobile App Development", the filtering logic finds posters with 'mobile' tag
- But these same posters also have 'website' tag, so they would also appear under "Website Development"

**Solution Required**:
The backend API needs to ensure posters have accurate, single-category tags. For example:
- Website Development posters should have: ['website']
- Mobile App Development posters should have: ['mobile', 'app'] or just ['mobile']
- No poster should have tags from multiple different categories

**Secondary Issue**: 
Line 292 assigns the same tags array to both `languages` and `tags` fields, which could cause confusion in language filtering later.
