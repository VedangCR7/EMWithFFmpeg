# Mobile Autopay Parsing Fix Report
## Issue Summary
The mobile app was incorrectly extracting the internal database subscription ID instead of the Razorpay subscription ID (`sub_xxxxxx`) from the backend API response. This caused Razorpay Checkout to fail with "Something went wrong" when trying to create the mandate.

## Root Cause (Incorrect Parsing Prioritizing Nested Data)

### **Problematic Original Code:**
```typescript
const data = response.data?.data || response.data;

const subscriptionId =
  data?.subscriptionId ||
  data?.razorpaySubscriptionId ||
  data?.id ||
  data?.subscription?.id;
```

**Issue:** This logic prioritized the nested `data` object, which contained internal database IDs rather than the actual Razorpay subscription ID.

### **Backend Response Structure:**
```json
{
  "success": true,
  "subscriptionId": "sub_xxxxxx",
  "razorpaySubscriptionId": "sub_xxxxxx",
  "data": {
    "subscription": {...},
    "razorpaySubscription": {...}
  }
}
```

**Problem:** The correct Razorpay ID was at the root level (`subscriptionId`), but the parsing logic was looking in the nested `data` object first.

## Files Modified

### 1. src/services/subscriptionApi.ts
**Location:** `createBusinessProfileAutopay` function (Lines 738-770)

**Original Code:**
```typescript
const data = response.data?.data || response.data;

const subscriptionId =
  data?.subscriptionId ||
  data?.razorpaySubscriptionId ||
  data?.id ||
  data?.subscription?.id;
```

**Fixed Code:**
```typescript
// Prioritize root-level fields from backend response
const root = response.data || {};
const nested = root.data || {};

console.log("🔍 Response structure:", {
  'root.subscriptionId': root.subscriptionId,
  'root.razorpaySubscriptionId': root.razorpaySubscriptionId,
  'nested.razorpaySubscription.subscriptionId': nested?.razorpaySubscription?.subscriptionId,
  'nested.subscription.razorpaySubscriptionId': nested?.subscription?.razorpaySubscriptionId,
  'nested.subscription.subscriptionId': nested?.subscription?.subscriptionId
});

// Always prioritize flat fields from backend
const subscriptionId =
  root.subscriptionId ||
  root.razorpaySubscriptionId ||
  nested?.razorpaySubscription?.subscriptionId ||
  nested?.subscription?.razorpaySubscriptionId ||
  nested?.subscription?.subscriptionId;

console.log("🎯 Final Razorpay Subscription ID:", subscriptionId);

if (!subscriptionId || !subscriptionId.startsWith("sub_")) {
  console.error("❌ Invalid subscription ID:", subscriptionId);
  throw new Error("Invalid Razorpay subscription ID received from backend.");
}
```

**Key Changes:**
- ✅ **Prioritize root-level fields:** `root.subscriptionId` and `root.razorpaySubscriptionId` checked first
- ✅ **Comprehensive logging:** Added detailed response structure analysis
- ✅ **Razorpay ID validation:** Ensures ID starts with "sub_"
- ✅ **Fallback logic:** Still checks nested objects as backup
- ✅ **Clear error messages:** Specific validation for invalid IDs
