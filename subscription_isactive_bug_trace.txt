File: Backend/eventmarketersbackend-main/src/utils/subscriptionUtils.ts

✅ CORRECT IMPLEMENTATION:
The database validation logic is CORRECT and strict:

```typescript
export function isSubscriptionActive(subscription: any): boolean {
  if (!subscription) return false;

  // Strict status check
  const hasActiveStatus = subscription.status === 'ACTIVE';
  
  // Payment ID must exist for active subscriptions
  const hasPayment = !!(subscription.paymentId || subscription.razorpaySubscriptionId);
  
  // Must not be expired
  const now = new Date();
  const endDate = subscription.endDate ? new Date(subscription.endDate) : null;
  const isNotExpired = endDate ? endDate >= now : true;

  return hasActiveStatus && hasPayment && isNotExpired;
}
```

VERDICT: Database logic is CORRECT - only status === 'ACTIVE' should return true.

SECTION 9 — ROOT CAUSE ANALYSIS
================================================================================

ROOT CAUSE:
The business profile subscription status logic incorrectly treats CANCELLED subscriptions
as active for the purpose of setting the isActive flag.

DATA FLOW:
1. User cancels Razorpay payment
2. Razorpay webhook updates business profile:
   - subscriptionStatus = 'CANCELLED'
   - isSubscriptionActive = true (may remain true temporarily)
3. Backend API /api/mobile/subscription/status with businessProfileId:
   - Reads business profile data
   - BUG: Includes CANCELLED status as valid for isActive
   - Returns { status: 'CANCELLED', isActive: true }
4. Frontend receives and displays incorrect active status

IMPACT:
- Users with cancelled payments still see active subscription
- Users may access premium features without paying
- Revenue loss and incorrect subscription state
