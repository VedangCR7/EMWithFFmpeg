2. NEW ROUTES ADDED
==============================================

MODIFIED ROUTES:
----------------
1. POST /api/mobile/auth/register
   - Now generates OTP for email registrations
   - Returns requiresVerification: true instead of token
   - Device-only registrations work as before

2. POST /api/mobile/auth/login  
   - Added email verification check before JWT issuance
   - Existing users without OTP records are treated as verified
   - Returns requiresVerification: true for unverified emails

NEW ENDPOINTS:
--------------
1. POST /api/mobile/auth/verify-email
   - Request: { email: string, code: string }
   - Validates OTP code, expiry, and attempts
   - Issues JWT token upon successful verification

2. POST /api/mobile/auth/resend-verification
   - Request: { email: string }
   - Rate limited: 60 seconds between requests
   - Generates new OTP and sends email

3. UPDATED REGISTRATION FLOW SUMMARY
==============================================

BEFORE (Original Flow):
-----------------------
1. User submits registration form
2. Backend validates and creates MobileUser, Customer, BusinessProfile
3. Backend generates JWT token immediately
4. User is logged in and navigated to main app

AFTER (New OTP Flow):
---------------------
1. User submits registration form
2. Backend validates and creates MobileUser, Customer, BusinessProfile
3. Backend generates 6-digit OTP code (15 min expiry)
4. Backend stores OTP in mobilePasswordResetCode table
5. Backend sends verification email
6. Backend returns requiresVerification: true (no token)
7. User must verify email to get JWT token

DEVICE-ONLY REGISTRATIONS (Unchanged):
------------------------------------
- Users without email/password get immediate JWT as before
- No OTP required for device-only registrations

4. SECURITY LOGIC SUMMARY
==============================================

OTP SECURITY FEATURES:
----------------------
• Code Length: 6 digits (numeric)
• Expiry: 15 minutes from generation
• Max Attempts: 5 failed attempts allowed
• Rate Limiting: 60 seconds between resend requests
• Secure Storage: Uses existing mobilePasswordResetCode table

VALIDATION LOGIC:
-----------------
• Email uniqueness check maintained
• Password hashing with bcrypt (12 rounds) unchanged
• JWT token generation only after email verification
• Existing users backward compatible (treated as verified)

ERROR HANDLING:
---------------
• Invalid code: Increments attempt counter
• Expired code: Returns specific error message
• Too many attempts: Blocks further attempts
• Rate limiting: Prevents email spam
• Email service failures: Graceful fallback to normal registration

6. NEW API ENDPOINTS SPECIFICATION
==============================================

POST /api/mobile/auth/verify-email
----------------------------------
Request Body:
{
  "email": "user@example.com",
  "code": "123456"
}

Success Response (200):
{
  "success": true,
  "message": "Email verified successfully",
  "data": {
    "user": { ... },
    "token": "jwt_token_here"
  }
}

Error Responses:
• 400: Invalid/expired code or missing fields
• 404: User not found
• 500: Server error

POST /api/mobile/auth/resend-verification
-----------------------------------------
Request Body:
{
  "email": "user@example.com"
}

Success Response (200):
{
  "success": true,
  "message": "Verification code sent to your email address",
  "email": "user@example.com"
}

Error Responses:
• 400: Missing email or already verified
• 404: User not found
• 429: Rate limited (wait 60 seconds)
• 500: Server error
