Business Logo Debug Report
==========================

ISSUE: Business Logo not updating on HomeScreen when switching profiles
SYMPTOM: Business name updates correctly, but logo continues showing old/default logo

1. Profile Switch Flow
======================

Profile switching is handled through the BusinessProfileContext global state:

Key Files:
- src/context/BusinessProfileContext.tsx
- src/screens/HomeScreen.tsx (lines 3063-3073)
- src/screens/BusinessProfilesScreen.tsx

Flow:
1. User taps profile in dropdown → handleBusinessProfileSelect() called
2. Profile found in userBusinessProfiles array
3. setSelectedBusinessProfile(profile) called in BusinessProfileContext
4. Profile saved to AsyncStorage with key '@selected_business_profile'
5. HomeScreen useBusinessProfile() hook receives new profile
6. Both userName and userAvatarUri should update

State Variables:
- selectedBusinessProfile: BusinessProfile | null (global context)
- userBusinessProfiles: BusinessProfile[] (local state)
- userProfile: User (from authService)

4. Cache Analysis
==================

Image Caching:
- OptimizedImage component uses ThumbnailImage for thumbnails
- ThumbnailImage caches in AsyncStorage with prefix '@thumbnail_cache_'
- Cache key: `user_avatar_${userProfile?.id || 'default'}_${selectedBusinessProfile?.id || 'personal'}`
- Cache expiry: 7 days
- Cache is based on profile ID, which should change when switching profiles

Profile Data Caching:
- BusinessProfileContext caches selected profile in AsyncStorage
- Key: '@selected_business_profile'
- UID validation prevents cross-user cache contamination
- Cache cleared on user logout

Business Profiles Caching:
- getUserBusinessProfiles() uses cacheService with 5-minute TTL
- Cache key: `business_profiles_user_${userId}`
- Stale data allowed while fetching fresh data

9. Root Cause Candidates
========================

A. Caching Issue:
- ThumbnailImage component might be caching old logo based on cache key
- Cache key includes selectedBusinessProfile?.id which should change
- But if profile ID is same across switches, cache might not invalidate

B. Data Mapping Issue:
- Backend might return logo in different field than expected
- Data mapping in getUserBusinessProfiles might not preserve logo correctly
- Logo field might be overwritten in mapping process

C. State Update Issue:
- selectedBusinessProfile might not be updating correctly
- useMemo dependencies might not be triggering re-render
- Profile object reference might not be changing

D. Image Component Issue:
- OptimizedImage/ThumbnailImage might have internal caching
- Component might not be re-rendering despite URI change
- cacheKey might not be changing appropriately

E. API Response Issue:
- Backend might not be returning logo field at all
- Logo field might be null/undefined in API response
- Logo URL format might be invalid

10. Recommended Fix Strategy
============================

Step 1: Add Debug Logging
- Add console.log in userAvatarUri useMemo to track URI changes
- Add console.log in getUserBusinessProfiles data mapping to verify logo fields
- Add console.log in handleBusinessProfileSelect to verify selected profile data

Step 2: Verify API Response
- Check backend API response structure for logo fields
- Confirm logo field names match frontend expectations
- Verify logo URLs are valid and accessible

Step 3: Check Cache Behavior
- Temporarily disable image caching to test if caching is the issue
- Verify cache key changes when switching profiles
- Clear image cache manually between profile switches

Step 4: Test State Updates
- Add useEffect to log selectedBusinessProfile changes
- Verify profile object reference changes on selection
- Test with different profile data to isolate caching vs state issues

Step 5: Fallback Testing
- Temporarily hardcode different logo URLs to test image component
- Test with simplified image component (plain <Image>) to isolate OptimizedImage
- Test with different logo field priorities in userAvatarUri logic

Most Likely Root Cause:
The issue is likely in the data mapping layer in getUserBusinessProfiles() where logo fields from the backend API response are not being correctly mapped to the frontend BusinessProfile interface, or the ThumbnailImage component is not properly invalidating cache when the profile changes.
