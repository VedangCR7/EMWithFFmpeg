PROBLEM IDENTIFIED
------------------

The mobile app was sending inconsistent payment failure statuses to the backend:

- CANCELLED status was being sent for user payment cancellations
- FAILED status was being sent for other payment failures
- Backend expects only: FAILED, SUCCESS, PENDING

This created inconsistent transaction states in the backend system.

VERIFICATION: NON-BLOCKING BEHAVIOR
-----------------------------------

✅ VERIFIED: reportPaymentFailure() function already implements safe non-blocking pattern:

```typescript
const reportPaymentFailure = async (orderId: string, status: string) => {
  try {
    console.log('🔴 Reporting payment failure to backend:', { orderId, status });
    
    // Non-blocking call to backend - don't await or throw errors
    fetch(`${api.defaults.baseURL}/api/mobile/transactions/update-status`, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${await AsyncStorage.getItem('authToken')}`,
      },
      body: JSON.stringify({
        orderId: orderId,
        status: status
      })
    }).catch(error => {
      console.warn('⚠️ Failed to report payment status to backend:', error);
      // Silently handle - don't show user-facing errors
    });
  } catch (error) {
    console.warn('⚠️ Error in reportPaymentFailure:', error);
    // Silently handle - don't affect user experience
  }
};
```

✅ Safe pattern confirmed:
- Runs inside try/catch
- Does not block UI
- Does not show errors to user
- Fails silently if network fails
