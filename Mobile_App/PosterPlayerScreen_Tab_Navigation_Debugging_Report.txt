# PosterPlayerScreen Tab Navigation Debugging Report

## 1. Root Cause Analysis

### PRIMARY ISSUE: Bottom Tab Navigation Keeps Screen Mounted
**Root Cause**: PosterPlayerScreen is registered in bottom tab navigator, which means it remains mounted and doesn't re-execute useEffect when business profile context changes.

**File**: `src/navigation/AppNavigator.tsx` (Lines 1121-1129)

### Critical Navigation Architecture:

#### Tab Navigator Configuration:
```tsx
<Tab.Screen
  name="PosterPlayer"
  component={PosterPlayerScreen}
  initialParams={{ originScreen: "MainTabs" }}
  options={{
    title: 'My Business',
    tabBarStyle: { display: 'none' },
  }}
/>
```

**Key Finding**: 
- ❌ **No lazy loading**: PosterPlayerScreen is not wrapped in `lazy()` 
- ❌ **No unmountOnBlur**: Screen stays mounted when switching tabs
- ❌ **No tab listeners**: No mechanism to detect tab switches

## 2. Bottom Tab Navigation Behavior Analysis

### React Navigation Tab Behavior:
1. **Screen Mounting**: All tab screens are mounted at app startup
2. **Persistent Mounting**: Screens remain mounted when switching between tabs
3. **useEffect Execution**: Only runs on initial mount, not on tab switches
4. **Context Updates**: BusinessProfileContext updates are received but don't trigger re-renders

### Expected vs Actual Behavior:

#### Expected (What SHOULD happen):
1. User switches profile on HomeScreen
2. BusinessProfileContext updates ✅
3. User taps "My Business" tab
4. PosterPlayerScreen should re-run useEffect with new context ✅
5. Posters reload with new category ✅

#### Actual (What ACTUALLY happens):
1. User switches profile on HomeScreen ✅
2. BusinessProfileContext updates ✅
3. User taps "My Business" tab ✅
4. PosterPlayerScreen is already mounted ❌
5. useEffect doesn't re-run (screen already mounted) ❌
6. Posters continue showing old category ❌

## 9. Root Cause Summary

**PosterPlayerScreen shows posters from previous business profile because:**

1. **PRIMARY**: Bottom tab navigation keeps screen mounted, preventing useEffect re-execution
2. **SECONDARY**: Profile change detection only clears templates but doesn't trigger reload
3. **TERTIARY**: useFocusEffect only resets language, doesn't reload posters
4. **QUATERNARY**: useEffect dependencies may not trigger re-execution in mounted screens

### The Core Issue:
In React Navigation's bottom tab navigator, when a screen is already mounted, changing context values doesn't automatically re-trigger useEffect hooks unless the dependencies are perceived as changed.

## 12. Recommended Fix Strategy

### OPTION 1: Force useEffect Re-execution (RECOMMENDED)

#### File: `src/screens/PosterPlayerScreen.tsx`

**Update Profile Change Detection (Lines 1156-1164)**:
```tsx
// CURRENT:
useEffect(() => {
  if (originScreen === "MainTabs" && globalSelectedProfile) {
    setAllTemplates([]);
    console.log('🔄 [PROFILE CHANGE] Business profile changed in My Business tab, reloading posters');
  }
}, [globalSelectedProfile?.id, originScreen]);

// CORRECTED:
useEffect(() => {
  if (originScreen === "MainTabs" && globalSelectedProfile) {
    // Force immediate reload
    setAllTemplates([]);
    
    // Force useEffect re-execution by updating categoryToUse trigger
    setTimeout(() => {
      console.log('🔄 [PROFILE CHANGE] Forcing poster reload for new profile');
      setAllTemplates([]); // This will trigger the main useEffect
    }, 0);
  }
}, [globalSelectedProfile?.id, originScreen]);
```

**OR Alternative - Add explicit reload trigger**:
```tsx
// Add a reload trigger state
const [profileReloadTrigger, setProfileReloadTrigger] = useState(0);

useEffect(() => {
  if (originScreen === "MainTabs" && globalSelectedProfile) {
    setProfileReloadTrigger(prev => prev + 1);
  }
}, [globalSelectedProfile?.id, originScreen]);

// Add to main useEffect dependencies:
}, [categoryToUse, posterLimit, initialPoster, selectedLanguage, setAllTemplates, profileReloadTrigger]);
```

### OPTION 2: Update useFocusEffect (ALTERNATIVE)

#### Update Focus Effect (Lines 438-446):
```tsx
// CURRENT:

    }
  }, [globalSelectedProfile, originScreen])
);
```
