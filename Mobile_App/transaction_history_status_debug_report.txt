ROOT CAUSE ANALYSIS
-------------------

**ISSUE 1: Subscription payment shows PENDING after modal close**

**Root Cause:** Modal ondismiss does NOT call reportPaymentFailure()

**Flow Analysis:**
```
User closes Razorpay modal
    ↓
modal.ondismiss called (Lines 489-494)
    ↓
Only UI reset: setIsProcessing(false), setPaymentInProgress(false)
    ↓
NO reportPaymentFailure() call
    ↓
Backend never receives failure status
    ↓
Transaction remains in PENDING state in backend
    ↓
TransactionHistory shows PENDING
```

**Expected Flow:**
```
User closes Razorpay modal
    ↓
modal.ondismiss called
    ↓
reportPaymentFailure(orderDetails.orderId, 'FAILED')
    ↓
Backend updates transaction status to FAILED
    ↓
TransactionHistory shows FAILED
```

**ISSUE 2: Business profile payment failure does not appear**

**Root Cause:** BusinessProfilesScreen modal ondismiss DOES call reportPaymentFailure() (recently fixed), but there might be a backend timing or type mismatch issue.

**Recent Fix Applied:**
- BusinessProfilesScreen.tsx now calls reportPaymentFailure() in modal ondismiss
- Same implementation as SubscriptionScreen

**Potential Remaining Issues:**
1. **Backend Type Mismatch:** Backend might send "BUSINESS_PROFILE" instead of "business_profile"
2. **Timing Issue:** Backend might not process the update-status call before the unified API fetch
3. **Caching Issue:** TransactionHistory service has 5-minute cache that might serve stale data
