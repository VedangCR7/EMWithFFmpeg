## 5. API Flow

### Verification Flow
1. **User Input**: User enters 6-digit code
2. **Validation**: Regex validation `/^\d{6}$/`
3. **API Call**: `loginAPIs.verifyResetCode({ email, code })`
4. **Success**: Navigate to `ResetPassword` screen with `{ email, code }`
5. **Failure**: Show Alert with error message

### Resend Flow
1. **User Action**: Click "Resend Code" button
2. **API Call**: `loginAPIs.requestPasswordReset({ email })`
3. **Success**: Show success Alert, start 60-second cooldown
4. **Failure**: Show error Alert

### API Endpoints
- **Verify**: `POST /api/mobile/auth/verify-reset-code`
- **Resend**: `POST /api/mobile/auth/forgot-password`

## 9. Potential Risks

### State Management Risks
- **Timer Conflicts**: Multiple timers could cause performance issues
- **Memory Leaks**: Interval cleanup must be properly handled
- **Re-render Issues**: Timer updates every second could affect performance

### User Experience Risks
- **Timer Confusion**: Two timers (expiry + cooldown) might confuse users
- **Auto-logout**: If implementing auto-logout on expiry, need clear messaging
- **Back Navigation**: Timer should continue or reset based on UX requirements

### Technical Risks
- **Background Behavior**: Timer behavior when app goes to background
- **Screen Reload**: Timer reset on screen refresh
- **Multiple Instances**: Multiple timers if component remounts

## 10. Recommendations for Implementing Timer

### Implementation Strategy
1. **Reuse Existing Timer Infrastructure**: Leverage existing timer pattern from resend functionality
2. **Clear User Communication**: Distinguish between expiry timer and resend cooldown
3. **Graceful Degradation**: Handle timer expiration without breaking app flow

### Code Implementation Points

#### Add New State
```tsx
const [codeExpiryTimer, setCodeExpiryTimer] = useState(0);
const [isCodeExpired, setIsCodeExpired] = useState(false);
```

#### Add useEffect for Expiry Timer
```tsx
useEffect(() => {
  let interval: NodeJS.Timeout | undefined;
  if (codeExpiryTimer > 0) {
    interval = setInterval(() => {
      setCodeExpiryTimer((prev) => {
        if (prev <= 1) {
          setIsCodeExpired(true);
          return 0;
        }
        return prev - 1;
      });
    }, 1000);
  }
  return () => {
    if (interval) clearInterval(interval);
  };
}, [codeExpiryTimer]);
```

#### Add Timer Display UI
```jsx
{codeExpiryTimer > 0 && (
  <View style={styles.timerContainer}>
    <Text style={[styles.timerText, { color: theme.colors.textSecondary }]}>
      Code expires in: {formatTime(codeExpiryTimer)}
    </Text>
  </View>
)}
```

#### Add Expiry Handling
```tsx
const handleVerify = useCallback(async () => {
  if (isCodeExpired) {
    Alert.alert('Code Expired', 'Your verification code has expired. Please request a new code.');
    return;
  }
  // ... existing verification logic
}, [isCodeExpired, ...]);
```

### Best Practices
1. **Timer Duration**: Use reasonable duration (5-10 minutes)
2. **Clear Messaging**: Explain timer purpose clearly
3. **Backup Mechanisms**: Allow manual resend even if timer expires
4. **Accessibility**: Add screen reader support for timer announcements
5. **Testing**: Test timer behavior in various scenarios (background, multitasking)

### Integration Considerations
- **Prop Interface**: Add `codeExpiryTime?: number` to component props
- **Timer Start**: Start timer on component mount or when code is resent
- **Timer Reset**: Reset timer when new code is requested
- **Error Handling**: Handle API errors without affecting timer
