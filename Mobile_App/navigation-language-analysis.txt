5. SIDE EFFECTS / RISK ANALYSIS
=================================

Potential Breakpoints if auto-setting language to "All":

LOW RISK:
✅ Language state reset - Already handled by existing logic
✅ Template filtering - 'all' option already supported
✅ User manual selection - Preserved via userManuallySelectedLanguageRef

MEDIUM RISK:
⚠️ Cached poster data - May show language-specific cached posters
⚠️ Business category filtering - May conflict with "All" language
⚠️ Service filter templates - May need reset when language changes

HIGH RISK:
❌ Subscription gating - Language change might trigger subscription checks
❌ Search filters - Active search might interfere with "All" language

Existing Safe Guards:
- userManuallySelectedLanguageRef prevents overriding user choices
- Language detection only runs when user hasn't manually selected
- Multiple category change handlers reset language appropriately

6. SAFE IMPLEMENTATION STRATEGY
===============================

RECOMMENDED APPROACH:

1. Detection Location:
   - Use useEffect() in PosterPlayerScreen.tsx
   - Check route.params.originScreen on component mount

2. Trigger Condition:
   ```typescript
   useEffect(() => {
     const { originScreen } = route.params;
     
     // Only auto-set if user hasn't manually selected language
     // AND user came from MyBusiness tab (no originScreen or MainTabs)
     if (!userManuallySelectedLanguageRef.current && 
         (!originScreen || originScreen === 'MainTabs')) {
       setSelectedLanguage('all');
       console.log('🔧 [AUTO-LANG] Set language to All from MyBusiness tab');
     }
   }, [route.params.originScreen]);
   ```

3. State Preservation:
   - Keep userManuallySelectedLanguageRef logic intact
   - Only auto-set when user hasn't made manual choice
   - Preserve existing language detection for other entry points

WHY THIS APPROACH IS SAFE:
- Uses existing refs and state management patterns
- Respects user manual selections
- Leverages existing originScreen parameter
- Minimal code change, maximum compatibility
