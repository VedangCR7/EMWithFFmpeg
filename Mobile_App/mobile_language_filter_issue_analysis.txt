4. API CALLS TRIGGERED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

On entering PosterPlayerScreen (from calendar date tap):
  [A] useEffect for businessCategory fires → calls:
      businessCategoryPostersApi.getPostersByCategory(categoryName, limit)
      Endpoint: /api/mobile/posters/category/{businessCategory}
      This returns ALL posters for the business (e.g., all "Salon" posters).

  [B] useEffect for calendarDate fires → calls:
      calendarApi.getPostersByDate(calendarDate)
      Endpoint: /api/mobile/calendar/posters/{date}
      This returns ONLY posters for that specific date.

On pressing language filter button:
  → selectedLanguage state changes
  → [A] businessCategory useEffect RE-FIRES because its dependency array
      at line 1137 includes selectedLanguage:

      }, [businessCategory, posterLimit, initialPoster, selectedLanguage, setAllTemplates]);
                                                                ↑
                                              ⚠️ CRITICAL BUG: This forces a
                                              full API re-fetch every time the
                                              language filter is changed

  → fetchBusinessCategoryPosters() executes again
  → businessCategoryPostersApi.getPostersByCategory() is called AGAIN
  → setAllTemplates(ensuredTemplates) overwrites the calendar date posters
     with business category posters

  [B] calendarDate useEffect does NOT re-fire (its deps are [calendarDate, initialPoster])
      so it cannot correct the overwritten state.

6. CACHE INSPECTION FINDINGS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  (a) calendarApi (src/services/calendarApi.ts)
      - Uses cacheService with cacheKey = "calendar_posters_date_{date}"
      - Cache TTL = 2 minutes
      - Also does clearCategoryCache() before fetching in business mode
      - Calendar cache is SEPARATE from business cache — no cross-contamination
        from the cache layer itself

  (b) businessCategoryPostersApi
      - Also uses cacheService with its own key per category name
      - Line 1025: businessCategoryPostersApi.clearCategoryCache(categoryName)
        is explicitly called BEFORE each fetch — meaning business posters are
        always freshly fetched, never stale

  (c) React Query / Axios caching
      - No React Query or Axios interceptor-level caching found in the codebase
      - All caching is done through the custom cacheService

  (d) AsyncStorage
      - AsyncStorage is used only for business profile persistence
        (useBusinessProfile context), NOT for poster data

  (e) useMemo / useCallback caching
      - filteredPosters (useMemo) depends on allTemplates which gets overwritten
        — this causes stale calendar poster data to be replaced silently
      - setAllTemplates is wrapped in useCallback with [businessCategory,
        greetingCategory, calendarDate] in its deps — the ref + logging wrapper
        is correct but cannot prevent the overwrite

  (f) FlatList keyExtractor
      - No custom keyExtractor issues found that would cause stale UI

  CACHE CONCLUSION:
      Cache is NOT the primary cause of the bug. The issue is pure React state
      overwrite caused by a misplaced navigation param and a misplaced dependency.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

    1. HorizontalFestivalCalendar sends businessCategory in nav params
    2. PosterPlayerScreen receives it → both calendar + business useEffects run
    3. Calendar effect correctly loads date posters into allTemplates
    4. Business effect also loads business posters into allTemplates (race condition)
    5. User taps language filter → selectedLanguage changes
    6. Business useEffect fires AGAIN due to selectedLanguage in deps
    7. Business API re-fetches and DEFINITIVELY overwrites allTemplates
    8. Calendar date context is completely lost

9. WHY BUSINESS IMAGES APPEAR INSTEAD OF DATE POSTERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Step-by-step sequence after user presses a language filter:

  1. User taps "Hindi" button on PosterPlayerScreen.
  2. React calls setSelectedLanguage('hindi').
  3. selectedLanguage state changes from 'all' → 'hindi'.
  4. React re-evaluates all useEffects whose deps include selectedLanguage.
  5. The businessCategory useEffect (line 991) has selectedLanguage in its deps
     (line 1137) → React QUEUES this effect to re-run.
  6. fetchBusinessCategoryPosters() executes:
       - Clears business category cache: clearCategoryCache(categoryName)
       - Calls API: /api/mobile/posters/category/Salon?limit=1000
       - Receives ~N business posters (e.g., all Salon posters)
       - Calls setAllTemplates(ensuredTemplates) → OVERWRITES calendar posters
  7. React re-renders: allTemplates now contains Salon business posters
  8. filteredPosters (useMemo) recomputes from new allTemplates filtered by
     selectedLanguage='hindi' → shows Hindi Salon posters
  9. User sees Salon/business images instead of the date-specific festival images.

  The calendar date posters are GONE from state. There is no mechanism to
  restore them without navigating back and re-entering the screen.
