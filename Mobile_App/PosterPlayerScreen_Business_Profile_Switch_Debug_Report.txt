POSTER PLAYER SCREEN - BUSINESS PROFILE SWITCH DEBUGGING REPORT
==========================================================================

ISSUE: Images/posters do not update when user switches business profile from HomeScreen dropdown

EXPECTED BEHAVIOR:
1. User switches business profile from HomeScreen dropdown
2. BusinessProfileContext updates selectedBusinessProfile  
3. User navigates to My Business tab
4. PosterPlayerScreen should display posters belonging to the new business category

ACTUAL BEHAVIOR:
PosterPlayerScreen still displays old category posters even after switching profile.

==========================================================================
ROOT CAUSE ANALYSIS
==========================================================================

PRIMARY ROOT CAUSE: STALE CATEGORY DERIVATION DUE TO ROUTE PARAMETER OVERRIDE

🔍 CRITICAL BUG #1 - Route Parameter Override (Lines 487-494)
---------------------------------------------------------------
Location: src/screens/PosterPlayerScreen.tsx:487-494

```typescript
const categoryToUse = useMemo(() => {
  if (originScreen === "MainTabs") {
    // When opened from bottom tab, use context-derived category
    return businessCategoryFromProfile;
  }
  // When opened from other screens, use route params (preserve existing behavior)
  return businessCategory || businessCategoryFromProfile;
}, [originScreen, businessCategoryFromProfile, businessCategory]);
```

PROBLEM: 
- When PosterPlayerScreen is opened from MainTabs (My Business tab), it correctly uses businessCategoryFromProfile
- However, businessCategoryFromProfile is derived from globalSelectedProfile (line 477-484)
- The businessCategoryFromProfile useMemo has dependency [globalSelectedProfile] only
- When business profile changes, globalSelectedProfile updates, businessCategoryFromProfile updates
- BUT the main poster loading useEffect (line 1170) depends on [categoryToUse, posterLimit, initialPoster, selectedLanguage, setAllTemplates]
- categoryToUse SHOULD update when businessCategoryFromProfile updates

DETAILED FLOW ANALYSIS
================================================================----------

STEP 1: User switches business profile from HomeScreen dropdown
- HomeScreen calls setSelectedBusinessProfile() from BusinessProfileContext
- BusinessProfileContext updates selectedBusinessProfile state
- BusinessProfileContext saves to AsyncStorage

STEP 2: BusinessProfileContext update propagation
- BusinessProfileContext state changes trigger re-render in all consumers
- PosterPlayerScreen receives new globalSelectedProfile via useBusinessProfile()
- globalSelectedProfile updates to new profile

STEP 3: Category derivation update
- businessCategoryFromProfile useMemo should recalculate with new globalSelectedProfile
- categoryToUse useMemo should recalculate with new businessCategoryFromProfile
- Main poster loading useEffect should trigger due to categoryToUse change

STEP 4: Poster loading
- useEffect at line 1024 should run with new categoryToUse
- Cache should be cleared for new category
- API should be called with new category
- New posters should be loaded and displayed

🚨 WHERE THE CHAIN BREAKS:

BREAK POINT #1 - Category Derivation Staleness
- businessCategoryFromProfile might not be updating despite globalSelectedProfile change
- This could happen if globalSelectedProfile reference doesn't change (object identity issue)

BREAK POINT #2 - Category Resolution Logic
- categoryToUse logic at line 487-494 might have issues
- When originScreen === "MainTabs", it uses businessCategoryFromProfile
- But businessCategoryFromProfile might be null or stale

BREAK POINT #3 - useEffect Dependency Issues
- Main useEffect at line 1170 depends on categoryToUse
- If categoryToUse doesn't change, useEffect doesn't run
- This could happen if categoryToUse reference remains the same

BREAK POINT #4 - Race Condition Between Multiple useEffects
- useFocusEffect (line 441) clears templates and cache
- Profile change useEffect (line 1172) also clears templates  
- Main loading useEffect (line 1024) loads new data
- These might interfere with each other

CONCLUSION
==========================================================================

The root cause appears to be in the category derivation and useEffect dependency chain in PosterPlayerScreen. When a business profile is switched:

1. BusinessProfileContext updates correctly
2. PosterPlayerScreen receives the new globalSelectedProfile
3. BUT the category derivation chain (businessCategoryFromProfile → categoryToUse) may not update properly
4. This prevents the main poster loading useEffect from triggering
5. Old posters remain displayed

The fix requires ensuring proper dependency propagation from globalSelectedProfile through the category derivation chain to the main loading useEffect, while eliminating race conditions between multiple useEffects that clear templates and cache.
