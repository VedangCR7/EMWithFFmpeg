TRANSACTION HISTORY DYNAMIC FIX REPORT
=======================================

Date: March 7, 2026
Engineer: Senior React Native Engineer
Scope: Remove hardcoded subscription references from transaction history

PROBLEM IDENTIFICATION
======================

**Issue**: Transaction history was showing hardcoded "Quarterly Pro" for Business Profile registration payments instead of the correct transaction name and dynamic values.

**Root Cause**: The `transactionHistory.ts` service contained hardcoded fallback values that were being used when backend data was incomplete, causing incorrect transaction titles to appear.

**Impact**: Business Profile payments displayed as "Quarterly Pro" instead of the appropriate business-related transaction name.

TRANSACTION TYPE HANDLING ANALYSIS
==================================

**Current Type Detection Logic**:
```javascript
// In transactionHistory.ts lines 84-97
const normalizedType = txn.type?.toLowerCase();
let plan: TransactionPlan = 'quarterly';
let type: 'subscription' | 'business_profile' = 'subscription';

if (normalizedType === 'business_profile' || (txn.plan && txn.plan.toLowerCase().includes('business'))) {
  plan = 'business_profile';
  type = 'business_profile';
} else if (txn.plan && txn.plan.toLowerCase().includes('year')) {
  plan = 'yearly';
  type = 'subscription';
} else {
  plan = 'quarterly';
  type = 'subscription';
}
```

**Transaction Types Supported**:
1. **SUBSCRIPTION** - Regular subscription payments
2. **BUSINESS_PROFILE** - Business profile registration payments
3. **PROMO** - Promotional subscription payments

**Type Detection Method**:
- Checks `txn.type` field from backend
- Falls back to `txn.plan` field analysis
- Defaults to subscription type if no business indicators found
