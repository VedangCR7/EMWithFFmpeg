===========================================================================
CARD WIDTH CALCULATION
===========================================================================

getCardWidth() function:
- Tablet (>=768px): screenWidth * 0.15 (6-7 cards)
- Medium phones (>=600px): screenWidth * 0.22 (4 cards)
- Regular phones (>=400px): screenWidth * 0.28 (3 cards)
- Small phones (<400px): screenWidth * 0.32 (3 cards, more spacing)

TemplateCard component receives cardWidth prop and renders with calculated dimensions.

===========================================================================
ROOT CAUSE IDENTIFICATION
===========================================================================

PRIMARY ISSUE: styles.searchCategoryContainer
- FIXED WIDTH: width: moderateScale(300) ≈ 150px on most devices
- This constrains category sections to a fixed narrow width
- Causes large empty space on the right side

SECONDARY ISSUE: styles.verticalTemplateContainer
- CENTER ALIGNMENT: alignItems: 'center'
- This centers individual template cards instead of stretching them
- Contributes to unused horizontal space

TERTIARY ISSUE: Multiple padding layers
- templatesSection: paddingHorizontal: moderateScale(8)
- sectionHeader: paddingHorizontal: moderateScale(10)
- verticalSearchList: paddingHorizontal: moderateScale(3)
- Combined padding reduces available width

===========================================================================
WHY HORIZONTAL SCROLL STILL WORKS
===========================================================================

The horizontal scrolling within category sections works because:
1. Each category has its own horizontal FlatList
2. The FlatList content can scroll within its fixed-width container
3. The scroll functionality is independent of the parent container width

===========================================================================
NESTED SCROLLVIEW ANALYSIS
===========================================================================

POTENTIAL ISSUE: VirtualizedLists inside ScrollView
- Main ScrollView (vertical) contains multiple FlatList components
- Category FlatLists are horizontal={true} (different orientation - OK)
- Search results FlatList is horizontal={false} (SAME orientation - PROBLEMATIC)

WARNING: "VirtualizedLists should never be nested inside plain ScrollViews with the same orientation"

The search results FlatList (vertical) is nested inside the main ScrollView (vertical), which can cause:
- Performance issues
- Scrolling conflicts
- Layout calculation problems

===========================================================================
LAYOUT CALCULATION EXAMPLE
===========================================================================

For a typical phone (screenWidth = 375px):
1. Main container: 375px full width
2. templatesSection padding: 8px × 2 = 16px
3. Available width: 375 - 16 = 359px
4. Category container: fixed 300px width
5. Empty space: 359 - 300 = 59px (16% of screen width)

For larger screens, the percentage of wasted space increases significantly.
