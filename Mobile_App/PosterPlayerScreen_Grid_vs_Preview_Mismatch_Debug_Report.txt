POSTER PLAYER SCREEN - GRID vs PREVIEW MISMATCH DEBUGGING REPORT
==========================================================================

ISSUE: Poster grid shows correct images for selected business category, but main preview 
continues showing previous category image and name.

OBSERVED BEHAVIOR:
✅ Poster grid correctly updates and shows posters for new category
❌ Main preview (selected poster view) shows old category image/name/metadata

This indicates grid state updates correctly, but selected poster state remains stale.

==========================================================================
ROOT CAUSE ANALYSIS
==========================================================================

PRIMARY ROOT CAUSE: USER SELECTION REFERENCE PREVENTS AUTOMATIC POSTER UPDATES

🔍 CRITICAL BUG #1 - User Selection Override (Lines 915-917)
---------------------------------------------------------------
Location: src/screens/PosterPlayerScreen.tsx:915-917

```typescript
// CRITICAL: Don't reset if user has manually selected a poster (via swipe or click)
// Check this FIRST before any other logic that might reset the poster
if (userSelectedPosterRef.current !== null) {
  return;
}
```

PROBLEM: 
- `userSelectedPosterRef.current` tracks when user manually selects a poster
- When this ref is set, ALL automatic poster updates are blocked
- The ref is set in `handlePosterSelect()` (line 2642) when user clicks/swipes
- BUT the ref is NEVER cleared when business profile changes
- This causes the main preview to freeze on the user-selected poster

🔍 CRITICAL BUG #2 - Missing User Selection Reset on Profile Change (Lines 1172-1180)
--------------------------------------------------------------------------------------
Location: src/screens/PosterPlayerScreen.tsx:1172-1180

```typescript

    // Clear templates to force reload with new profile
```

PROBLEM: This useEffect clears templates but DOES NOT clear `userSelectedPosterRef.current`
- Grid updates because `allTemplates` is cleared and refetched
- Preview remains stale because `userSelectedPosterRef` blocks automatic updates
- The ref should be reset when business profile changes

- Even casual browsing sets this ref
- Once set, it blocks ALL automatic poster updates

BREAK POINT #2 - Multiple useEffects Blocked by Same Ref

- Language filter useEffect blocked (Line 2536)
- Any other poster update useEffect would also be blocked
- The ref acts as a global update blocker

==========================================================================
WHY GRID UPDATES BUT PREVIEW DOESN'T
==========================================================================

GRID UPDATES CORRECTLY BECAUSE:
1. Business category loading useEffect (Line 1024) runs when categoryToUse changes
2. This useEffect calls setAllTemplates([]) then setAllTemplates(newTemplates)
3. No user selection checks block template updates
4. Grid renders from allTemplates state directly

PREVIEW REMAINS STALE BECAUSE:
1. setCurrentPoster() calls are blocked by userSelectedPosterRef.current
2. Multiple useEffects that should update currentPoster have early returns
3. The ref was set during previous user interaction and never cleared
4. Business profile change doesn't reset user interaction state

==========================================================================
ASYNC RACE CONDITIONS
==========================================================================

RACE CONDITION #1 - useEffect Execution Order
- Business category loading: setCurrentPoster(posterToSet) 
- Route param effect: if (userSelectedPosterRef.current) return;
- If route param effect runs after business loading, it blocks the update

RACE CONDITION #2 - Ref Timing
- User sets ref by clicking poster
- Business profile changes
- Template reload happens
- But ref check blocks poster update before template reload completes

RECOMMENDED FIX STRATEGIES
==========================================================================

STRATEGY #1: Clear User Selection Ref on Profile Change
- Add userSelectedPosterRef.current = null in profile change useEffect
- This will unblock automatic poster updates when business profile changes

STRATEGY #2: Make User Selection Context-Aware
- Don't block updates for legitimate category changes
- Only block updates during active user interaction sessions
- Reset ref when navigating away or changing business profiles

STRATEGY #3: Fix useEffect Priority Order
- Business profile changes should take precedence over user selection
- Category changes should override user interaction refs
- Reorder useEffect execution or add context checks

STRATEGY #4: Separate User Interaction Tracking
- Use different refs for different types of user interaction
- Distinguish between temporary browsing and persistent selection
- Allow automatic updates for category changes

STRATEGY #5: Add Business Profile Change Detection
- Explicitly detect when business profile changes
- Reset all user interaction state on profile changes
- Force poster refresh on category switches

CONCLUSION
==========================================================================

The root cause is that `userSelectedPosterRef.current` acts as a global blocker for 
all automatic poster updates. When a user manually selects a poster, this ref is set 
and never cleared. When the business profile changes:

1. ✅ Poster grid updates because allTemplates state changes
2. ❌ Main preview remains stale because setCurrentPoster calls are blocked
3. ❌ Multiple useEffects have early returns due to the user selection ref
4. ❌ Business profile change doesn't reset user interaction state

The fix requires clearing the user selection ref when business profiles change 
and making the blocking logic more context-aware to allow legitimate category 
updates while preserving user choice during active interactions.
