============================================================
ORIGINAL PARSING BUG
============================================================

ISSUE IDENTIFIED:
- Backend returns: response.data.subscription
- Mobile was parsing: response.data.data
- This caused subscriptionData to be null
- Result: Subscription appeared inactive despite valid backend response

BACKEND API RESPONSE STRUCTURE:
```json
{
  "success": true,
  "subscription": {
    "isActive": true,
    "planId": "...",
    "planName": "...",
    "expiryDate": "...",
    "autoRenew": true
  }
}
```

MOBILE LOGS BEFORE FIX:
```
Subscription status fetched:
{
 "isActive": false,
 "plan": null,
 "expiryDate": null
}
Subscription access: DENIED
```

ROOT CAUSE:
❌ const subscriptionData = response.data?.data ?? null;
✅ Should parse: response.data?.subscription

============================================================
UPDATED PARSING LOGIC
============================================================

FILE: src/services/subscriptionApi.ts
FUNCTION: getStatus()

FIX IMPLEMENTED:
```typescript
// BEFORE (INCORRECT):
const subscriptionData = response.data?.data ?? null;

// AFTER (CORRECT):
const subscriptionData = 
  response.data?.subscription ??
  response.data?.data ??
  null;
```

COMPATIBILITY:
- ✅ Handles response.data.subscription (current backend)
- ✅ Falls back to response.data.data (legacy compatibility)
- ✅ Prevents breaking changes if backend structure changes
